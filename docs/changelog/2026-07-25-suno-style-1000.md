# Suno style limit raised to 1000 characters

**Date:** 2026-07-25  
**Status:** implemented (sandbox deployed — migration `071`)

## Summary

Suno V5 / V5_5 customMode accepts **style up to 1000 characters**. CAMXORA still truncated to 255 because `suno_tasks.style` was `VARCHAR(255)` and `SUNO_STYLE_MAX_LENGTH` mirrored that. Long Music Prompts (e.g. Eurodance ~800 chars with male/female vocal lines) were cut mid-sentence before reaching Suno.

## Product impact

- **Before:** Style prompts longer than 255 chars were truncated; trailing production and vocal gender lines often never reached Suno.
- **After:** Full description content up to 1000 chars is stored and submitted (still trimmed if over 1000).

## Technical impact

- Migration `071_suno_style_1000`: `ALTER TABLE suno_tasks ALTER COLUMN style TYPE VARCHAR(1000)`
- `SUNO_STYLE_MAX_LENGTH = 1000` in `vocal_profile.py`
- Pydantic `SunoRequest.style` / generation router `max_length=1000`

## Migration / deploy

1. Deploy platform API + run `alembic upgrade head` (071).
2. No desktop change required — style is resolved server-side on Suno submit.
3. Re-submit / retry Suno on existing drafts to send the longer style (old suno_tasks rows keep truncated style until re-queued).

## Incident

**2026-07-25 ~17:41–17:47 +07 (sandbox):** After hotfix restart, API lifespan hung on `071_suno_style_1000` while a concurrent `alembic upgrade` also ran. Requests returned `500 Database pool not initialized` — admin/app login failed. Migration had already completed (`suno_tasks.style` = VARCHAR(1000), alembic `071`). **Fix:** `systemctl restart camxora-api`. Verified `signup-mode` OK and login returns `401` (not pool 500) on API + admin proxy.

## Follow-ups

- Optional vocal-cast control (male/female/both) still useful so gender is explicit at the start of style.
- Title limits remain separate (V5 title ≤100); not changed here.
- Prefer running alembic **before** restarting the API (or ensure only one migrator holds the DB lock) to avoid startup hang.
