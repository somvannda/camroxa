# Desktop 1.4.2 — video export duration fix + MP3 duration headers

**Date:** 2026-09-23
**Branch:** `release/1.4.2`
**Surfaces:** camxora_python (desktop)
**Status:** implemented; installer built and published

## Summary

Video export could finish with an MP4 **shorter than the source audio**, so the
export gate rejected the track ("video export did not produce a usable output")
and the pipeline stalled before merge. Two root causes:

1. **libsndfile under-decode.** `soundfile` (libsndfile/minimp3) decoded some
   48 kHz VBR MP3s to only part of the track (observed 117s of a 208s song). The
   render then produced a matching short video, and the gate rejected it.
2. **Stale analysis cache.** A cached analysis written before the decode fix held
   the short duration and was reused, so the decode fix never ran on existing
   installs.

Separately, Suno's CDN MP3s have **no Xing/Info header**, so `ffprobe` and media
players estimated the duration from file size and over-reported it by 3–23s. A
**correct** MP4 therefore looked shorter than its MP3.

## Product impact

- Exported MP4 duration now matches the source audio (verified per track).
- Existing audio-analysis caches are invalidated on upgrade, so the decode fix
  takes effect without a manual cache clear.
- Merge only proceeds when the exported MP4 actually matches the audio length.
- Downloaded MP3s now carry a Xing/Info header, so MP3 and MP4 report the **same**
  duration in players and `ffprobe`.
- Also in this build: Studio is hidden from the desktop sidebar, and ffmpeg
  console popups during export/merge are suppressed.

## Technical impact

- `visualizer/audio.py`: after the `soundfile` decode, compare the decoded length
  to `ffprobe` and fall through to the ffmpeg decoder when it is materially short
  (same fix shape already used for Opus-in-MP4).
- `shared/services/audio_analysis_cache.py`: `CACHE_VERSION` 2 → 3, and reject a
  cached `duration_sec` materially shorter than the file's real duration.
- `features/video/lib/export_output_validity.py`: `export_media_looks_complete`
  keeps the **source-audio** truncation check even when the rendered length is
  known, so a short render cannot reach merge.
- `shared/lib/suno_mp3_download.py`: new `ensure_mp3_duration_header()` re-muxes
  an MP3 with `ffmpeg -c copy -write_xing 1` (lossless) to add the duration
  header.
- `shared/workers/data_workers.py`: call it after download and when backfilling
  existing files during download sync.
