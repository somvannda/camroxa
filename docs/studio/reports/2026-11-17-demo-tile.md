## 2. What the demo project actually contains

`buildDemoProject()` in `camxora.com/lib/studio-seed.ts` returns the payload
`createStudioProject` already accepts (`SeededProject`):

| Field | Value | Why |
|---|---|---|
| `title` | `Drum & Bass Demo` | The captured tile label; the project the tile opens carries the same name |
| `bpm` | `174` | The reference demo project runs at 174 BPM (S17 / `CAPTURE_LOG.md`) |
| `data.tracks` | **1** track, `Drum & Bass Loop`, olive drum family colour, `clipIds: ["clip-demo-loop"]` | One Audio Track holding the loop, as captured for a single-part start |
| `data.lanes` | **1** clip, `start: 0`, `duration: 4`, `audioUrl: /seed/demo-loop.wav` | Our own 4 s loop (mono, 22.05 kHz — verified against the WAV header) |
| `data.masterChain` | compressor + 2× EQ | The captured master rack is not empty (S26/S48) |

The audio is `camxora.com/public/seed/demo-loop.wav`, an asset we already ship (it is the same
file the waveform/upload e2e tests use). **No Suno generation, no provider call, no copied
audio, no invented metadata.** The clip is a plain `audioUrl` lane, which is exactly what the
editor's playback path consumes (`StudioEditorShell` → `clip.audioUrl`), so “press play” works
on open.

`masterRack()` was extracted from `buildSeedFromSong` so both seeds share the same three-entry
rack instead of duplicating it; `buildSeedFromSong` output is unchanged (its unit test still
asserts `["compressor", "eq", "eq"]`).

**Shell** — `camxora.com/components/studio/StudioEditorShell.tsx`

- `openDemoProject()` calls `createStudioProject(buildDemoProject())`, rewrites the URL with

- This mirrors the existing `?clip=` import flow, so the project loads through the normal
  `getStudioProject` path — tracks, clips, autosave, history and presence all behave as usual.
- Failures surface in the editor's existing error banner; nothing is swallowed.

## 8. Limitations / what is deliberately not claimed

- The demo is **one loop on one track**, not the reference's 17-track “Drum & Bass Demo”. It is
  a real, playable arrangement we own; presenting it as the captured project would be a lie, so
  CLONE_DEFINITION §5 says exactly what it is.
- The waveform is real (decoded from our WAV), the BPM is the captured demo's tempo; the loop
  was not produced by Suno and is not described as such anywhere in the UI.
- `Video Tutorial` is untouched and remains the single recorded absence in that row.
- The e2e test was written against existing selectors (`.se-chip`, `.se-clip`, `.se-lane`,
  `.se-track-name`, the waveform's `role="img"`), but has not been executed in this worktree.
